# BANDEIRA 运维访问与发布索引

> 用途：为后续发布、验收和故障排查提供稳定入口。本文不记录密码、私钥、Token、生产 `.env`、数据库凭据或服务器地址。

## 受控资料

- 服务器访问、主机密钥校验和 GitHub 操作，以交付给项目负责人的受控交接包为准；该资料不应提交到本仓库。
- 使用当前操作者的专属凭据。凭据仅可在其本机受保护的 SSH 目录使用，不得复制到仓库、文档、聊天记录或构建产物。
- 发布与回滚的详细步骤见 [production-deployment-runbook.md](production-deployment-runbook.md)。

## 每次发布的固定顺序

1. 只以已合并的 `main` 提交作为发布来源，并记录目标提交 SHA。
2. 在生产机先进行只读连通性核验：身份、受控 sudo、容器状态、当前 release 路径与 readiness。
3. 执行数据库备份并确认备份文件存在，再构建和切换 release。
4. 回读容器健康状态、readiness、后台入口、Flyway 迁移与目标 SHA。
5. 确认真实奖励、钱包、提现、付款，以及尚未单独放行的团队/导师现金能力仍保持关闭。

## 失败与恢复

- 发布失败时，不得以删除生产数据或重置数据库作为恢复手段。
- 保留失败 release、构建日志和备份名称；按发布手册切回上一个已验证 release。
- 任何涉及真实资金能力的开关、凭据轮换或数据库恢复，均需单独书面授权并执行后验核查。
