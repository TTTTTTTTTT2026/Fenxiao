# 钻石、黑金高级等级验收标准 V1

> 状态：业务基础口径已确认，适用于当前人工验收流程。经营结果的**具体 KPI**尚未确认；在此之前只能由有权限的运营人员逐期确认，系统不得自行判定“经营通过”。
>
> 依据：需求方《用户等级按以下条件判断》截图（2026-09-18）及 [用户等级、邀请分成与团队奖励决策](20260918-user-grade-invitation-and-team-reward-decision.md)。

## 1. 共用原则

1. 等级不使用本人收入金额、下级累计收入金额、积分、购买课程、注册、入群或推荐奖励作为额外门槛。
2. 新星、银牌、金牌只统计累计**直接邀请**的有效用户；间接邀请不计入等级人数。
3. 铂金、钻石、黑金均不允许仅因推荐链中出现对应等级成员而自动升级：必须有培养关系和经营验收记录。
4. 正常停止业务不自动降级。只有刷号、虚假收入、伪造成绩经高权限人工核实后，才能撤销证据并重新核定。
5. 通过高级等级验收不等于开启团队经营分成、导师现金激励、奖励、余额、提现或付款；这些能力继续独立关闭和审批。
6. 验收人应是具备等级验收权限的运营人员；最终负责人任命仍须高权限确认并保留审计记录。

## 2. 钻石验收

### 2.1 必须满足的事实

候选人必须同时满足：

- 已具备铂金资格；
- 实际培养两名**不同**的金牌成员；
- 两名金牌成员各自关联不同的小团队；
- 两个相关小团队分别完成连续两个自然月的经营验收。

“实际培养”必须由人工录入并确认，不可仅根据邀请链自动推断。可使用现有群聊记录、辅导记录、复盘摘要、团队运营材料作为证据；不要求额外制作复杂报告。

### 2.2 连续两个月的口径

- 以完整自然月为周期；例如 1 月、2 月连续通过，才能构成一段连续两个月的验收。
- 两个小团队均须分别有两个月连续通过记录；不能以一个团队的两个月记录替代另一个团队。
- 任一团队出现月份缺失、不通过、撤销或观察期不完整，即不形成通过结论；后续须重新形成连续两个月记录。

### 2.3 系统自动校验与人工确认边界

系统可自动校验：铂金前置资格、培养对象人数为两人、培养对象身份为金牌、对象和团队不重复、月份连续且完整。

系统不得自动校验：小团队是否实际完成经营、经营质量是否合格。当前缺少确认的经营 KPI，这一结论必须由运营按月确认，并保存说明与证据引用。

## 3. 黑金验收

### 3.1 必须满足的事实

候选人必须同时满足：

- 已具备钻石资格；
- 实际培养两名**不同**的钻石成员；
- 明确其负责的业务范围；
- 该负责业务完成连续三个自然月经营验收。

负责业务必须通过可审计的业务范围标识承载，例如团队 ID、业务单元或运营区域；不能仅以邀请链存在来认定责任范围。

### 3.2 连续三个月的口径

- 以完整自然月为周期；例如 1 月、2 月、3 月连续通过，才构成一段连续三个月验收。
- 任一月份缺失、不通过、撤销或观察期不完整，即不形成通过结论；后续须重新形成连续三个月记录。

### 3.3 系统自动校验与人工确认边界

系统可自动校验：钻石前置资格、培养对象人数为两人、培养对象身份为钻石、对象不重复、责任范围已指定、月份连续且完整。

系统不得自动校验：所负责业务的经营质量或通过与否。具体经营 KPI 由业务后续补充前，只能由运营逐月确认并留存证据。

## 4. 防重复与证据规则

- 同一培养对象不能在同一观察期被重复计入同一候选人的两个培养名额。
- 同一小团队不能在同一观察期同时作为同一候选人的两个独立培养团队。
- 已撤销、被高权限人工排除或证据失效的培养/经营记录不得继续作为升级依据。
- 每条培养和经营确认至少应保存：候选人、培养对象或业务范围、观察起止日期、确认人、确认时间、说明、证据引用及状态。

上述防重复规则用于保证验收可审计，不会改写邀请关系、历史团队成员关系或已确认的低级别资格。

## 5. 推荐状态流

```text
验收中
→ 培养已确认
→ 各期经营验收已确认
→ 经营职责已确认
→ 待负责人任命
→ 负责人已确认
```

- 钻石：两名金牌和两个小团队均满足连续两个月后，才可进入经营职责确认。
- 黑金：两名钻石和负责业务满足连续三个月后，才可进入经营职责确认。
- 任何阶段均不自动发奖或开启团队经营分成。

## 6. 待业务补充的唯一经营指标

业务后续只需为每个经营周期补充“通过”的可量化判断指标，例如活跃用户、合规、留存、团队产出或其他经营质量指标；未确认前，禁止把未审批的数值阈值写入代码或将空壳团队自动判为通过。
