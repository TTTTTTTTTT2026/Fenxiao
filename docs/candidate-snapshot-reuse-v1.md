# 候选历史快照复用：第一阶段

## 目标和不变项

相同应用、业务日期的输入、决策依赖和逐条结果全部相同时，后续运行只新增运行摘要及直接引用，不再复制整批历史明细。不是按总额、人数或随机样本判重，也不是缓存整条业务处理。

- `McnIncomeBusinessFactPipeline` 原顺序保持：来源事实整理 → 候选演算 → 正式邀请积分核对 → 有效资格/等级刷新。
- 每次仍重新生成当前计算结果和非支付团队预留，仍调用 `InvitationRewardAccountService.reconcile`。没有修改收入、分佣比例、积分兑换、绑定日资格、冻结、解冻、冲正、提现或发奖规则。
- 本期减少重复历史 INSERT 及索引写入；当前结果 DELETE/INSERT、原有演算、读取成本仍存在。没有量化生产 binlog/备份节省率，不承诺立即释放已有磁盘空间。
- 不清理、扫描去重、归档或改写现存历史；不执行生产 SQL、补算、备份清理或表空间重组。

## 存储与读取

V81只新增三张表，不ALTER历史大表：

| 表 | 内容 |
| --- | --- |
| mcn_candidate_snapshot_lock | TIMO/LINKY各一行，事务级应用锁 |
| mcn_candidate_snapshot_owner | 独立快照所有者、应用/日期/格式/指纹唯一键、完整明细条数、压缩决策依赖 |
| mcn_candidate_snapshot_ref | 每个新运行直接引用所有者，不形成引用链 |

有变化时：照常保存完整 `mcn_income_reward_candidate_run_item`，登记所有者和自引用。无变化时：保留新的 `mcn_income_reward_candidate_run`（自己的runId和运行摘要），直接引用已有所有者；不会更新该所有者或其明细。

`sample(runId)`先验证调用者run存在和范围，解析一次直接引用，仍返回调用者runId/应用/日期；按原有SHA2排序及正收益/阻断配额抽样。没有引用的旧run仍按原runId读完整旧明细。引用范围错误或所有者明细缺失时抛错，不伪装为空结果。所有历史读取消费者已全仓检索：运行抽样在该服务，汇总读取run，正式积分读取当前结果而不是历史明细。API DTO、权限及前端未改。

新代码没有删除所有者或引用的路径；FK防止孤立引用。未来归档/清理必须保护所有引用者，不能仅根据所有者的运行时间删除证据。旧明细表尚无关联FK，不允许绕过服务人工删除其所有者明细。

## 判重证据和编码

`CANDIDATE_EVIDENCE_V1`使用SHA-256。固定顺序编码行数、字段类型、UTF-8字节长度及内容；NULL独立标记，与空串区分；BigDecimal用去无意义尾零的十进制（不经double）；日期、Instant和LocalDateTime用稳定ISO表示。输入按source_event_id、结果按source_event_id/reward_level排序。字符串不依靠分隔符连接，不把空值或缺数据当零。

覆盖实际参与本次决策的：

- 来源事件/不可变raw ledger ID、修订、业务日、来源用户/公会/状态、发生时间、原始金额/币种/单位、粒度/来源时区/完整区间。
- 来源及逐级收款用户ID、当前账号状态、国家；不包含昵称、手机号、令牌、无关资料修改时钟。
- 实际匹配的核验账号和核验时间（或明确无匹配）；绑定自然日算法标识。
- 所选策略ID/代码/类型/应用/国家/状态/有效区间/批准时间、层级启用/费率/冻结配置。
- 所选公司分成版本ID/版本/费率/有效区间/状态；相同费率的新版本也生成新证据。
- 实际查询的邀请关系及首日回退关系（包括被区间条件排除的首次记录）：用户、邀请人、关系版本、起止时间或明确无匹配。
- 计算版本、团队预留常量、运行统计；完整当前结果所有业务列，包括base、阻断、异常、零金额、来源修订、规则/收款人/公司基数等。

排除随机runId、数据库自增行ID、projected_at/created_at/updated_at等纯运行时钟。金额相同不代表证据相同。尚未执行到的分支不虚构“已匹配”的规则。积分兑换和正式账户冻结配置属于后续账户核对，不作为跳过其执行的条件，本期仍每次执行它们。

每个不同快照除完整明细外，还保存一次gzip压缩的决策依赖编码。编码为一连串行：大端int32字段数；每字段一字节类型（0=NULL，1=decimal，2=整数，3=boolean，4=时间，5=字符串/枚举）；非NULL后跟大端int32字节长度及UTF-8内容。结果行只进入指纹、不再放进压缩依赖（结果已完整保存在run_item）。新版本改变任何决策依赖或编码约定必须升级格式/算法标识。压缩依赖包含受控业务标识，不返回到现有API、公共日志或聊天；没有新增外部查询入口。

## 事务与并发

- 两个应用独立加锁，同应用跨日期串行；原因是修订可能把同一事件移出原日期，现有代码会跨日删除旧当前记录，单日期锁不足。
- pipeline在来源事实重建前取得 `SELECT ... FOR UPDATE`，候选refresh入口也取得同一锁。锁属于外层事务、提交/回滚时自动释放，不使用需要手工释放的会话命名锁。
- 输入读取、当前重建、摘要、指纹和引用登记在同一事务内。锁不是短暂包围最后一个INSERT；新服务若脱离事务直接调用会拒绝执行。
- 数据库唯一约束是额外防线。锁超时、死锁或明细写失败会抛出异常并回滚外层事务，不在部分提交后继续记录成功，也不在方法内部自调用重试。需要重试时由原调用者对整个事务重试；本期不扩大既有任务重试政策或增加后台任务。
- 不同应用仍可能在正式账户中访问同一收款人，沿用既有账户行锁/异常策略，不声称本次消除了全系统所有死锁。原有演算时长可能影响同应用锁等待，启用时需观察；没有批量并发提速承诺。

## 分阶段发布和回滚（必读）

配置：`app.mcn-candidate-snapshot.reuse-enabled` / `MCN_CANDIDATE_SNAPSHOT_REUSE_ENABLED`，默认false，Compose明确透传默认false；不是奖励或财务开关。

1. **兼容阶段A**：合并、另获发布授权后，先部署本版并执行V81，保持复用false。写入仍逐run完整副本，兼容读已上线。确认没有引用型run后，可回滚PR176应用（保留V81结构），不能假称阶段A已经降低快照增长。
2. **启用阶段B**：阶段A验收、确认所有应用实例/历史读取者已兼容且用户明确同意启用后，由运维修改该单项参数为true并按Runbook重新创建后端，其他配置保持。只观察正常任务，不为测试而触发生产收入重算。
3. **启用后的回退**：关闭复用并继续使用兼容读版本，后续写入恢复完整副本，已有引用继续可读。不得直接退回PR176或更早JAR：它们会按新runId查不到明细。回滚基线必须是通过验收的阶段A兼容镜像；没有该镜像时仅可向前修复，不能把恢复数据库当默认手段。

本PR本身不构成阶段A发布、阶段B启用、生产清理或任何资金开关的授权。既有.env需原样继承，仅新增默认关闭的本项配置；不把旧Runbook中的历史默认值机械覆盖现网MCN/SMS等已批准配置。

## 自动验收与剩余范围

- 本地H2合成链路：重复运行摘要增长而明细不增长；每次run可抽样、旧run兼容、禁用后读取新引用、损坏引用拒绝；修订/币种/移日/空集/零值/未配置/冻结/国家/关系/策略/同费率版本变化；同总额逐项变化、输入物理顺序；正式积分幂等、解冻后重复演算及撤销冲正。
- CI Backend tests增加隔离MySQL8.4 service，使用仅127.0.0.1且固定测试库前缀URL；每例创建独立合成schema，结束仅删除本例schema。Flyway真实执行V81、唯一索引/FK、同应用并发等待/其他应用可继续、写入异常全事务回滚、原MySQL抽样函数及积分幂等。MySQL测试未配置时明确跳过，不能将本地H2通过声称为MySQL通过。
- 不改前端；CI仍保留全量前端检查及仓库保护。实际测试数量/结果以PR和对话日志记录为准。
- 生产验收只读观察：新增run/引用/所有者数量，新增run_item及压缩依赖字节、锁等待/失败、任务耗时、binlog增量和备份体积。单次合成验证不推算生产节省比例。
- 历史归档、在线窗口、物理空间回收、触发合并、按变化增量演算、扩容及备份策略调整均未实施。
