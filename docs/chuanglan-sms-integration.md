# 创蓝验证码短信：受控接入与联调

## 范围

- 使用创蓝新加坡节点的 `sign/nonce` HTTPS 发送接口：`https://sg-intapi.tig253.com/send/sms`。
- 只替换现有 `SmsSender`，不改变验证码生成、10 分钟有效期、60 秒重发间隔、5 次校验和邀请注册规则。
- 默认 `SMS_PROVIDER=LOG_ONLY`，且数据库中的「创蓝短信接口开关」默认关闭；任一门槛关闭都不请求创蓝，而是沿用脱敏日志和受限后台验证码审查。部署侧显式设置 `CHUANGLAN` 并配置凭据后，最高管理员可在「配置中心 → 验证码审查」开启真实发送。后台开关可即时关闭，无须重启，并留审计日志。
- 开启后不再限定测试手机号名单，符合号码格式的请求可触发付费短信。现有规则是同一号码 60 秒重发间隔、每个 UTC 自然日最多申请 5 次；**尚无按请求 IP 或全站总量的限额，不能将同号限流视为充分的费用防护。**

## 配置

从安全渠道将凭据放入运行环境变量，不写进 Git、镜像、日志或文档：

| 环境变量 | 用途 |
| --- | --- |
| `SMS_PROVIDER` | 部署侧安全门槛：设置为 `CHUANGLAN` 才允许后台开启真实发送；仅设置该变量**不会**自动发短信 |
| `SMS_CHUANGLAN_ACCOUNT` | 创蓝 API 账号 |
| `SMS_CHUANGLAN_PASSWORD` | 创蓝 API 密码，仅用于本地生成签名 |
| `SMS_CHUANGLAN_BASE_URL` | 默认固定为新加坡 `sign/nonce` HTTPS 端点 |

发送请求使用 UTF-8 JSON；号码转成“国家码+号码”的纯数字形式，不带 `+` 或 `00`。印尼 `+62` 请求另外携带 `senderId=BANDEIRA`，其他地区暂不传 `senderId`。签名按创蓝文档对 `nonce` 和所有非空请求字段（包括印尼请求的 `senderId`）的键名按 ASCII 升序排列，拼接键和值，再附 API 密码计算小写 MD5。只将 `code=0` 视为提交受理；提交受理不等于最终送达。应用不自动重试不确定的提交结果，以免重复扣费。

## 验证码短信语言

验证码处理按收件号码的国际区号固定选择通道及语言，不依赖用户资料中的国家或客户端界面语言。当前客户端开放的五个区号如下，示例中的六位数字仅为占位：

| 区号 | 短信正文示例 |
| --- | --- |
| 印尼 `+62` | `[BANDEIRA] kode verifikasi anda adalah 123123` |
| 中国 `+86` | 不调用创蓝；验证码仅保存为内部审查记录，供授权管理员在后台提取 |
| 香港 `+852` | `[BANDEIRA] 您的驗證碼是 123123` |
| 墨西哥 `+52` | `[BANDEIRA] Su código de verificación es 123123` |
| 巴西 `+55` | `[BANDEIRA] Seu código de verificação é 123123` |

印尼正文遵照已报备格式，除替换六位验证码外，不添加句号、有效期或其他提示。业务方于 2026-10-07 转述短信服务商反馈：印尼短信失败与请求缺少 `senderId` 有关，已核实该值为 `BANDEIRA`；该字段是独立请求参数，不是正文前缀，实际收件仍需上线后验收。`+86` 是明确的内部审查特例：无论创蓝总开关是否开启，均不调用创蓝，审查列表标记为“内部审查/内部记录”；即使有人直接调用创蓝发送器，发送器也会拒绝 `+86` 请求。未识别的旧区号暂保留原英文正文，避免发送路径行为在本次改动中意外中断；如未来开放新地区，须先确定一个固定语言及对应模板并补测试。业务方于 2026-10-07 确认除印尼既有报备外，其他地区新文案无需单独审批；真实收件验收由业务方本人跟进。仍须核对供应商侧地区发送权限，`code=0` 不代表短信已送达。

## 后台开关和上线顺序

1. 部署时配置 `SMS_PROVIDER=CHUANGLAN` 和账号密码；凭据只放在安全环境配置中，不进入代码或运营页面。`SMS_CHUANGLAN_TEST_NUMBERS` 已弃用，即使旧部署环境中仍存在也不会限制收件人。数据库迁移 `V67` 初始化开关为关闭，升级部署本身不触发真实发送。
   生产 Docker Compose 已显式传递上述环境变量至后端；若生产 `.env` 不设置它们，容器仍以 `LOG_ONLY` 启动，不会调用创蓝。
2. 最高管理员登录「配置中心 → 验证码审查」，确认服务器配置显示“已就绪”，再人工开启。开启后有效格式的号码都可申请发码，仍受同号限流约束；关闭后立即回到原有后台查看验证码方式。开启前应明确短信费用监控与应急关停责任。
3. 使用授权测试号码跑一次**应用内**获取验证码、登录闭环，核对创蓝受理和手机收件；本地发送器单条联调成功不能替代生产应用验收。公开推广前仍需补足按 IP／全站总量的防刷和费用上限。

后台接口 `GET/POST /admin/sms-delivery` 仅最高管理员可用；查询不返回密码、完整测试号码或验证码。开关变更写入 `operation_audit_log`。当部署侧适配器未就绪时，后台拒绝开启；当服务器侧改回 `LOG_ONLY` 时，即使数据库仍保留“已开启”的历史设置，实际发送仍关闭。

## 已执行的联调与待办

- 2026-09-28：本机到新加坡端点 443 端口可连通；获授权测试请求由创蓝以 `114` 拒绝，表示实际发送出口 IP 未在账号白名单。经同一 Java `HttpClient` 直连核验，该出口是 `223.160.220.186`。此前 PowerShell 查询得到的 `69.17.3.75` 是系统代理出口，**不是** Java 短信请求的出口；只加白该代理地址后再次测试仍返回 `114`。
- 2026-09-28：从生产服务器出口发起一条不落地凭据、不修改生产应用的单条测试请求；创蓝以 `112` 拒绝，文档解释为“产品配置错误”。此响应不同于本机白名单错误，同样不是提交成功或送达证明。
- 2026-09-28：服务商后续加白 Java 直连出口并更新配置后，本地授权香港号码单条联调获 `code=0`，用户确认手机实际收件。此为发送器联调，不代表代码已部署或应用内登录闭环已验收。
- 当前本地测试号码的单条提交与收件已通过；后续再接状态报告回调，以获得运营商侧送达结果。上线前需补足按 IP／全局额度的防刷保护并经业务批准逐步扩大号码范围。
