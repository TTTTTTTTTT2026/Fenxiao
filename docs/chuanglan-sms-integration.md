# 创蓝验证码短信：受控接入与联调

## 范围

- 使用创蓝新加坡节点的 `sign/nonce` HTTPS 发送接口：`https://sg-intapi.tig253.com/send/sms`。
- 只替换现有 `SmsSender`，不改变验证码生成、10 分钟有效期、60 秒重发间隔、5 次校验和邀请注册规则。
- 默认 `SMS_PROVIDER=LOG_ONLY`；这只记录脱敏事件，不发送短信。只有显式切换为 `CHUANGLAN` 且配置凭据与非空测试号码白名单时才会发送。
- 本阶段仅允许已授权的测试号码，每个号码每个 UTC 自然日最多申请 5 次验证码。**不得把测试白名单当作公开发码的最终防刷方案。**

## 配置

从安全渠道将凭据放入运行环境变量，不写进 Git、镜像、日志或文档：

| 环境变量 | 用途 |
| --- | --- |
| `SMS_PROVIDER` | 显式设置为 `CHUANGLAN` 才启用真实发送 |
| `SMS_CHUANGLAN_ACCOUNT` | 创蓝 API 账号 |
| `SMS_CHUANGLAN_PASSWORD` | 创蓝 API 密码，仅用于本地生成签名 |
| `SMS_CHUANGLAN_TEST_NUMBERS` | 以逗号分隔的获授权完整国际号码；不能为空 |
| `SMS_CHUANGLAN_BASE_URL` | 默认固定为新加坡 `sign/nonce` HTTPS 端点 |

发送请求使用 UTF-8 JSON；号码转成“国家码+号码”的纯数字形式，不带 `+` 或 `00`。签名按创蓝文档对 `nonce` 和非空请求字段的键名按 ASCII 升序排列，拼接键和值，再附 API 密码计算小写 MD5。只将 `code=0` 视为提交受理；提交受理不等于最终送达。应用不自动重试不确定的提交结果，以免重复扣费。

## 已执行的联调与待办

- 2026-09-28：本机到新加坡端点 443 端口可连通；获授权测试请求由创蓝以 `114` 拒绝，表示实际发送出口 IP 未在账号白名单。经同一 Java `HttpClient` 直连核验，该出口是 `223.160.220.186`。此前 PowerShell 查询得到的 `69.17.3.75` 是系统代理出口，**不是** Java 短信请求的出口；只加白该代理地址后再次测试仍返回 `114`。
- 2026-09-28：从生产服务器出口发起一条不落地凭据、不修改生产应用的单条测试请求；创蓝以 `112` 拒绝，文档解释为“产品配置错误”。此响应不同于本机白名单错误，同样不是提交成功或送达证明。
- 需服务商确认：测试账号是否已启用新加坡 `sign/nonce` 国际短信产品、香港测试目的地是否已报价或开通；如需从本机继续联调，应临时加白 Java 直连出口 `223.160.220.186`。此问题未解决前，不继续重复请求。
- 获得 `code=0` 后，还须测试人员确认手机收到短信；后续再接状态报告回调，确认运营商送达结果。上线前需补足按 IP／全局额度的防刷保护并经业务批准逐步扩大号码范围。
