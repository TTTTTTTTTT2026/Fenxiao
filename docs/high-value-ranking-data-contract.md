# 高价值用户排行：真实数据口径与发布核验

此报表仅展示已完成的 UTC 自然日、自然周或自然月；必须指定一个应用及一个国家，公会可选。用户是否入榜以周期结束时的价值标签为准；未人工标记的用户视为一般用户，不入榜。国家按用户当前档案筛选，不作历史国家快照。相同指标值按用户 ID 升序排列。

| 展示指标 | 读取来源 | 口径 |
| --- | --- | --- |
| 自身收入（分佣积分） | `invitation_commission_report_event` | 周期业务日期、所选应用／公会内，归属该用户的直接和间接分佣积分净额；不把解冻转账重复算作收入。 |
| 直接下级收入（裸钻） | `mcn_income_shadow_ledger_projection`，按原始事件时间关联邀请关系 | 周期业务日期、所选应用／公会内，直属下级的 MCN `SETTLED`、`BOUND_FINAL` 收入／调整净额，尚未扣平台分成；仅计该应用的钻石单位。 |
| 新增裂变人数 | Linky 核验尝试或 Timo 绑定历史，按成功时间关联邀请关系 | 周期内首次成功绑定当前应用的直属下级人数；同一用户在同一应用只计一次。 |

筛选「对接运营」时，上述三项业务事件均按事件发生时的负责人归属；人员转交不会改写过去。入榜资格的高价值标签使用周期末历史记录。报表只读，不生成奖励或修改资金数据。排序在服务端完成后分页，查询按国家和高价值标签缩小候选人，再分批读取投影，不扫描分佣会计流水表。管理员权限和应用／公会／国家数据范围在 API 层校验。

## 发布前后核验

1. V77 将已有分佣投影补充 `business_date`、`source_guild_id`、`occurred_at`，从已存在的分佣账本与分佣条目一次性回填，并创建查询索引。上线前由运维评估表行数、DDL 锁、长事务与可用空间，建立且验证新备份；不要在未核量时假定迁移时间。
2. 迁移后只读核对分佣投影三列的非空覆盖和旧数据行数，再核对 Linky/Timo、不同公会和运营转交前后的样例。禁止为了“补数据”重新发奖、回写邀请关系或人工触发用户核验。
3. 页面不含虚拟排行行。若所选周期的 MCN 影子投影运行天数不足，页面显示覆盖警告；警告不代表零收入是真的零。正式数据准确性仍需与生产只读样本比对，不以本地测试通过代替生产验收。
4. 应用版本回滚不自动撤销 V77 表结构或删除历史记录。若回滚至未写入 V77 新列的旧后端，它仍可能继续写入可空的新投影列，造成新事件的日期／公会／时间维度缺口；应停止将这段数据用于排行、只读核对缺口，并制定受控补投影方案。不能把数据库结构兼容误认为数据已完整回滚。迁移失败时先确认数据库与 Flyway 的实际状态，再按发布 Runbook 处理，不盲目重跑。
