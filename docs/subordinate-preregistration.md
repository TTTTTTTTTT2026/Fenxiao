# 邀请人增加下级与预注册

关联 Issue #191。用户确认开发，交付后先本地验收；本文不构成发布或生产数据操作授权。

## 用户行为

- 入口：我 / 设置（`/account`）→ 增加下级（`/account/add-subordinate`）。
- 同应用已成功绑定的正常邀请人，输入所选国家手机号及 Timo/Linky 数字 ID，为尚不存在的手机号创建一份预注册申请。
- 手机号先查重，兼容既有带/不带 `+` 及展示分隔符的记录。正常、冻结、注销及有效预注册占用均不允许再次创建。格式与确定性账号占用冲突不调用上游核验。
- 申请列表按邀请人隔离，分页、脱敏展示。仅编辑表单按有权且未结束的申请读取原始输入。可修改、切换应用及撤回，修改不延长原截止时间。手机号本人认领后，邀请人不能修改其手机号及国家。
- 各应用沿用正式核验渠道、目标公会和资格判断。Timo 使用与本人提交相同的 provider / scope resolver / lifecycle / campaign；Linky 使用既有完整登记、核验和归属服务。仅权威成功才显示已完成。

## 状态与关系

- 新建 `PRE_REGISTERED` 账号，记录来源邀请人，尚不签发登录会话、旧令牌、正式邀请/导师/团队关系或应用所有权。
- 应用成功时，在事务内建立正式关系、保存真实绑定和核验事实，并变为 `ACTIVE`。已发生的官方入会时间不被预注册或首次登录时间替代；既有收入、资格及法定货币规则保持。
- 手机号本人通过既有验证码登录时，认领同一用户、建立正式关系并转 `ACTIVE`，原申请及截止时间不变，不要求重新输入邀请码。
- `submitted_at + 72h` 为绝对期限。到期仅结束未完成申请，清除其临时唯一占用；尚未认领/激活的档案变为 `PRE_REGISTRATION_EXPIRED` 并解除手机号，档案、申请和核验/审计记录保留。已经正常的账号、手机号、关系、绑定和收益不删除。
- 普通注销仍为永久状态，不用于预注册到期。预注册账号冻结再解冻时仍回到预注册，不能绕过认领/核验直接变正常。
- 如本人认领后已经在原流程提交该应用绑定，预注册流程不覆盖此绑定，转交该原流程处理；列表说明实际原因。

## 调度与并发

- 提交或编辑后立即尝试，后续后台每分钟扫描最多20份到期/应重试申请，优先处理已到期项。连续等待退避为1、5、30分钟，调度扫描和每次写入均检查绝对截止时间。
- `app.pre-registration.scheduler-enabled` 默认true，隔离测试为false；`app.pre-registration.poll-interval` 默认60000毫秒。关闭调度不延长截止时间。
- V89新增64个稳定数据库锁槽，手机号及平台账号按键映射、有序加锁；既有本人提交和上级协助提交共用账号锁，避免不同表各自查重后同时占用。申请的有效手机号及账号还有数据库唯一约束。
- 账号行锁协调认领、修改、核验、冻结与到期；申请版本拒绝旧页面修改和迟到失败处理。锁后刷新实体，避免事务一级缓存覆盖已提交的新状态。
- 上游调用后的成功写入再检查截止时间。迟到成功抛出并回滚关系、激活、所有权和绑定，随后独立结束过期申请，不能自动复活。
- Linky原服务的失败尝试独立保留；原业务事务回滚后才记录申请等待结果。应用 ID 和手机号不进入普通日志及通用审计明文。

## API

邀请人会话经 `X-Distribution-Token` 鉴权，基础路径为 `/api/distribution/team/{inviterId}/pre-registrations`：

| 操作 | 方法与路径 |
|---|---|
| 分页/资格 | GET `?page=0&size=20` |
| 首次提交 | POST |
| 修改表单输入 | GET `/{id}/edit-input` |
| 修改并核验 | PATCH `/{id}`，携带revision |
| 撤回 | DELETE `/{id}?revision=...` |

## 验证及发布边界

集成测试覆盖两应用、OTP认领、迟到成功回滚、定时恢复、越权、查重、修改/撤回、并发提交及旧协助入口。MySQL条件测试在独立数据库验证V88→V89、现有用户保留、可空唯一占用释放及跨连接行锁。浏览器验收使用真实构建和本机合成数据，不调用真实MCN或短信。

发布必须先通过产品验收和CI，按既有Runbook验证备份并执行V89。新账号状态需要相应版本支持；产生预注册档案后，不能假定PR190旧二进制可直接读新枚举并回滚。发布前应准备包含新状态兼容读取的回滚版本，保留V89及历史，不通过删除迁移/历史恢复旧程序。当前交付不执行生产部署。
