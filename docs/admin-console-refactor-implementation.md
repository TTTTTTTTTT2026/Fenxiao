# 管理后台前端渐进重构：实施与验收清单

> 2026-10-08。本文件记录开发分支的实施边界，不代表生产已发布或业务验收通过。决策依据见工作区根目录的 `BANDEIRA管理后台重构决策.md`。

## 不变边界

- 旧后台 `/admin` 和原有 hash 导航保留。新后台只占用管理域名的 `/console` 路径；`/admin/` 管理 API 不改路径。
- 新旧页面调用同一组 `/admin/` 服务端接口，继续使用现有 `bandeira_admin_session` Cookie（Path 为 `/admin`）和 `X-Admin-Session`。权限、写入、审计以服务端为准，不建第二套业务规则。
- 本分支不部署生产，不改变生产数据，不迁移写入页面。C 端与伙伴域名在外层 Nginx 明确拒绝 `/console`。

## 迁移顺序与验收闸门

1. **只读试点**：用户列表在真实测试账号下与旧版逐项对照：权限、昵称、邀请人、国家/等级、平台绑定、公会来源、注册时间排序、筛选、分页、空态、错误态。不得用前端自行排序替代服务端分页排序。
2. **其他只读模块**：分销概览、公会目录、等级列表、只读报表等按风险逐页迁移。每页单独确认 API、权限、时区与字段口径，避免一次搬运旧组件的大量状态。
3. **结构继续拆分**：从旧 `App.tsx` 分出管理端页面/会话/查询处理，并将 API 类型和适配器按领域整理；CSS 先建立作用域与截图基线，再移除可证明无用的旧覆盖。拆分阶段不换旧页面外观和业务行为。
4. **敏感写入最后**：财务、风控、验证码审查、国家/公会归属、密码开通、系统配置等写入页逐项迁移。每项验证服务端权限、审计、确认步骤、失败处理和重复提交，必要时继续跳旧版。
5. **灰度与退役**：由运维按发布 Runbook 发布，验证管理域名直达刷新、Cookie、反向代理、C/伙伴域名隔离和回滚；旧 `/admin` 保留至业务明确批准退役。

## 当前未完成

- 新版只覆盖用户列表，尚未代替完整管理端；旧 `App.tsx`、`App.css`、`api.ts` 仍需分阶段深度拆分。
- 尚缺真实后台会话下的新旧页面数据对照、可访问性和移动宽度检查。
- 新版 ProComponents 工作台产物体积偏大，需确定目标浏览器/网络条件并做加载性能验收。
- 未执行生产部署、生产访问或写入操作。

## 第二批开发增量（2026-10-08；基于首批 PR #146，尚未合并）

为避免在待审 PR #146 上追加未经单独审阅的内容，第二批从其 head 新建接续分支。新版工作台把用户列表移成独立懒加载页面，并按旧后台现有菜单权限配置组织 `/console/users`、`/console/guilds` 路由；旧后台仍用原 hash 路由。新增的“平台公会目录”只读页调用现有 `/admin/distribution/platform-guild-directory` 及 `/sync-runs`，不创建新服务端规则、表或写入入口。平台选项取现有管理员会话 `platformScope`，请求带平台参数，响应展示时再按平台过滤，避免跨工作区混显；最终数据授权仍由服务端执行。

旧 `App.tsx` 中的日期展示及状态标签映射按原有逻辑抽成共享模块，新旧页面可复用，旧版外观和业务口径不变。新增路由/角色、平台范围、数据隔离、原接口及授权头、共享展示口径测试。用本地虚拟管理员和虚拟公会数据检查了菜单切换、Linky 有数、Timo 空态、跨平台响应过滤、中文用户列表空态与管理员名称布局；这些不是生产数据验收。

随后在同一接续 PR 内又完成一小块旧端的行为保持拆分：将旧后台展示用的卡片、表格、状态标签等组件迁到 `src/admin/LegacyPresentation.tsx`，将旧“平台公会目录”的 JSX 迁到 `src/admin/LegacyGuildDirectorySection.tsx`；状态、请求、菜单切换和写入能力仍留原位。新增旧组件静态渲染回归测试，核对原有锚点、类名、关键字段、空态与平台标签。旧 `App.tsx` 从本批开始前的 7,586 行降到 7,415 行；这仅是结构改善，不等于其余管理页面已拆完，也不声称性能改善。

前端 219 项测试、lint、build 均通过；构建仍提示约 1.01 MB 的 Table chunk，加载性能尚未测量。真实测试账号下的新旧字段/权限对照、后续只读页、旧端大组件/CSS/API 的进一步拆分、写入页迁移和生产发布仍未完成。此增量应单独审阅，并以前一批合并为前置条件。
