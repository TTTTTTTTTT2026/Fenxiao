# P1、P2 与 MCN 数据运营全链路验收清单 V1

> 目的：用于本轮非资金验收。候选、预留、等级、团队和导师关系均不得形成真实奖励、余额、提现、付款或外部资金动作。

## 0. 开始前安全检查

- 后台登录后确认真实奖励引擎、提现、付款保持关闭。
- 仅使用已批准的只读 MCN 收入事实窗口；不得开启持续同步或真实资金消费。
- 准备一个具有已绑定、已定稿收入的测试平台与日期；Timo、Linky 分别抽查一组。

## 1. MCN 收入事实与运营闭环

1. 在“配置 → 收入影子账本”选择平台和业务日期，读取已有结果、查看数据质量。
2. 核对来源事实、最新事实、已绑定已定稿、未匹配、等待定稿和作废数量；人工重新投影只在填写原因后执行。
3. 对“未归属平台账号”和“等待 MCN 定稿”逐项登记处理结论。复核不会修改 MCN 原始事实，也不会产生奖励。
4. 对含已绑定、已定稿事实的日期执行“按当前证据演算候选”，确认候选页面显示来源收入、公会公司分成快照、公司业务收入基数、直邀 10%、间邀 3%与 2%预留。
5. 抽取核验样本：验证 A→B→C 中，C 的收入只让 B 获 10%、A 获 3%，不会向第 3 层传播；2%只记录预留，不进团队利润和任何资金账户。

## 2. P1：有效用户、七级等级与高级验收

1. 在“用户等级”按平台刷新/读取有效用户资格。确认资格仅来自最近 7 个**完整**自然日中至少 3 个不同日期的本人真实、可结算聊天业务收入；当天、注册、课程、推荐奖励均不计入。
2. 同页核对“永久资格”和“当前活跃”分列。先前曾达标但近期不活跃的用户仍保留永久资格，不自动降级。
3. 建立并启用新星、银牌、金牌规则，固定累计直接有效邀请人数 3 / 10 / 30；确认 A→B→C 时 A 只统计 B。
4. 对金牌达标用户做“立即复核”：应自动创建团队、产生团长权限与团队成员历史关系；不得开启团队经营奖励。
5. 铂金验收：录入两名不同银牌成员、不同小组、各自至少 30 天观察及末 7 天指标；两条证据后才允许确认培养。
6. 钻石模拟验收：录入两名不同金牌成员、不同团队范围、各自连续两个完整自然月。使用历史完整月份可立即验证，无需等待真实两个月。
7. 黑金模拟验收：录入两名不同钻石成员、明确经营范围、连续三个完整自然月。系统不得把缺月、非月初起始或未来结束日期当作通过。
8. 对任一高级验收依次确认培养、经营、职责，确认只让记录进入负责人确认流程，不触发奖励或团队经营分成。
9. 超级管理员才可对已核实刷号、虚假收入、伪造业绩做有效用户纠偏；普通停业不得纠偏或自动降级。

## 3. P2：团队与团队奖励边界

1. 打开“团队列表”，核对负责人资格、建队状态、任命状态、父团队、当前成员和最近经营事实可见。
2. 验证 B 成为团队负责人后，B 的新团队独立存在，但 B 的 A 团队历史成员关系不被删除。
3. 团队经营奖励一栏必须显示“全局关闭”；不应提供勾选或启用操作。
4. 直接调用或通过页面尝试启用团队经营奖励，应被拒绝；只允许把遗留许可关闭。
5. 旧运营分红规则和旧 5%路径不得再创建、审批或生成候选；历史数据仅供审计。

## 4. 导师与积分边界

1. “导师列表”仍可新建/编辑导师资格、设置学员归属并查看已归属学员；这些操作与邀请关系独立。
2. 导师现金激励页面不应再出现在主菜单；旧链接只显示历史审计，不能新建或启用规则。
3. “代币积分换算”按 Timo、Linky 原始代币单位分别维护，保存必须二次确认；积分事实仅用于审计，不作为七级升级或团长任命权威。

## 5. 验收完成判定

全部检查通过后，记录每个平台、业务日期、操作者、结果、异常处理引用和页面截图。任何一个步骤出现真实奖励、余额、提现、付款、第三层邀请候选、自动团队经营奖励或自动导师现金激励，立即停止验收并按 P0 安全缺陷处理。
