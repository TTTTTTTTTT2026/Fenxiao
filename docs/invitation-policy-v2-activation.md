# 两层邀请分成测算规则：内测启用记录

## 口径与范围

- 适用范围：Timo、Linky × BR、ID、MX，共六个明确的平台/国家组合。
- 基数：MCN 已定稿、已绑定且可结算的原始收入，乘以收入用户所属公会在收入发生时有效的公司分成比例，得到公司业务收入。
- 测算：直邀 10%，间邀 3%；最多向上两层，三级关闭。各等级当前相同，未来差异化需另行版本化变更。
- 2% 为未来团队奖励预留记录，不参与 10%／3% 的金额计算，不可发放。收入事实修订、撤销或变更业务日期后，重算会同步清理失效预留。
- 该迁移只启用**非付款的测算规则**；`REWARD_ENGINE_ENABLED`、`REAL_FINANCE_ENABLED`、`LIFECYCLE_SHADOW_ONLY`、团队与导师奖励开关均不变。

## 生效与审计

Flyway V65 在部署时为六个范围建立已启用版本，`effective_from` 使用生产 MySQL 的当前时间；生产 MySQL 与应用使用 UTC+0。旧收入不追溯，仅收入发生时间不早于生效时间的事实可匹配新规则。已有当前有效策略的范围不会被覆盖或重叠插入；历史旧策略保留。

当前不发奖、且发奖等待期尚无业务确认，因此接口必填的两层 `freeze_days` 暂记为 0，**不得据此推断允许即时发奖**。正式发奖前必须另行确认等待期，并通过新版本规则、财务授权及独立验收启用。

后台入口“财务管理 → 邀请裂变分成”为只读台账；不在页面修改比例。迁移文件、Flyway 版本记录及 `commission_policy` 的生效/审批字段共同保留此次研发变更记录。

## 发布后只读验收

1. 确认 Flyway V65 成功、六个 `CP-INV-V2-*` 规则均为 `ACTIVE`，比例、层级、UTC 生效时间正确，且没有重叠的当前有效规则。
2. 确认真实发奖、财务、团队经营分成及导师现金激励仍关闭。
3. 以首笔**生效之后**的已定稿且可匹配 MCN 事实，核对公司比例、发生时邀请关系及两层测算；不为此制造生产收入。
4. 若尚无真实匹配事实，记录“配置已生效、业务结果待验”，不得把零候选误称为计算故障，也不得把本地模拟结果称为生产端到端验收。
